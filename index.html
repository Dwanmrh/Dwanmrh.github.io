How a project goes live

The workflow I follow, from the first requirement to a site people can use.

  1. Requirements

    Map the business process into modules and user roles, then design the relational database schema.

  2. Application logic

    Server-side code on an MVC framework, most often Laravel, with an ORM and middleware for access control and business rules.

  3. Interface

    Responsive pages built with templates and a CSS framework, most often Blade and Tailwind CSS, plus JavaScript where a page needs it.

  4. Live site

    Built and tested in a local development environment, then deployed to production hosting with its own domain.

Undergraduate thesis, presented at ICIC 2026

SIPKKJ: health and physical fitness assessment system

Replaces the manual scoring of Rikkes (health examination) and Kesjas (physical fitness) tests for Setukpa students, which was previously done with paper, scoring handbooks and Excel.

First author of the paper on this system

Requirements analysis

  • Mapped the initial and final Rikkes and Kesjas assessment flow into system modules.
  • Defined the access model: admin, Rikkes officer, Kesjas officer, and students who see only their own results.
  • Compared PHP frameworks to justify the technology choice in the thesis research.

Key features

  • Per-student input or bulk Excel import, with a downloadable template.
  • Automatic Kesjas scoring by gender and age group, including test items a student did not take.
  • Final score reports, rankings, platoon and class filters, and Excel export.

How it works

Research: I presented the paper on this system, "Rule-Based Automation of Health and Physical Fitness Assessment in a Web-Based Information System", as first author at ICIC 2026, co-authored with Asroni and Slamet Riyadi.
